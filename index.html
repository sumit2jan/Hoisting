JavaScript Hoisting

Interview-ready notes — Hindi + Code examples ke saath. Ekdum detail mein, easy language mein.

Core Concept
Interview Important
ES6 Ready
Definition
Hoisting ka matlab hai — JavaScript code run karne se pehle, engine poora code scan karta hai aur saari variable / function declarations ko memory mein upar (top) le jaata hai.

Sirf declaration move hoti hai — value/initialization nahi. Value wahin rehti hai jahan tumne likhi hai.
JavaScript Execution Ke 2 Phases
⬡ PHASE 1 — Creation

Pura code scan karo.
Saari declarations dhundho aur memory mein register karo. Variable = undefined, Functions = poori body.

⬡ PHASE 2 — Execution

Code line by line chalao.
Values assign hoti hain, functions call hote hain, actual kaam hota hai yahan.

1 — var Hoisting
var → hoist hota hai + undefined se initialize hota hai
Tumne likhavar
console.log(name);     // ???
var name = "Alice";
console.log(name);     // ???
▶ undefined
▶ "Alice"
JavaScript ne actually kya kiyabehind the scenes
var name = undefined;  // ⬅ JS ne upar le aaya
console.log(name);     // undefined
name = "Alice";          // ab value mili
console.log(name);     // "Alice"
2 — let & const Hoisting (TDZ)
let / const → hoist hote hain BUT initialize nahi hote → Temporal Dead Zone (TDZ)

TDZ (Temporal Dead Zone) — woh period jab variable declare hua hai memory mein lekin abhi initialize nahi hua. Iss time mein access karo toh ReferenceError aayega.

let ka exampleTDZ Error
console.log(age);  // ❌ ReferenceError!
let age = 25;
console.log(age);  // ✅ 25
✕ ReferenceError: Cannot access 'age' before initialization
const ka exampleTDZ Error
console.log(PI);   // ❌ ReferenceError!
const PI = 3.14;
console.log(PI);   // ✅ 3.14
✕ ReferenceError: Cannot access 'PI' before initialization
3 — Function Declaration Hoisting
Function declarations → POORI tarah hoist hoti hain (naam + body dono)
Pehle call, baad mein defineWorks! ✅
greet();                    // ✅ Kaam karega!

function greet() {
  console.log("Namaste!");
}
▶ "Namaste!"

Kyunki function declaration mein naam aur poori body dono Phase 1 mein hi memory mein aa jaati hai.

4 — Function Expression Hoisting
Function expressions → variable ke rules follow karte hain (var/let/const ke hisaab se)
var ke saathTypeError
sayHi();                  // ❌ TypeError!
var sayHi = function() {
  console.log("Hi!");
};
✕ TypeError: sayHi is not a function

Kyunki var sayHi hoist hua undefined ke saath — aur undefined() call karo toh TypeError aata hai.

let/const ke saathReferenceError
sayBye();                 // ❌ ReferenceError! (TDZ)
const sayBye = function() {
  console.log("Bye!");
};
✕ ReferenceError: Cannot access 'sayBye' before initialization
5 — Class Hoisting
Classes → let/const ki tarah hoist hoti hain → TDZ apply hota hai
Class exampleReferenceError
const obj = new Car();    // ❌ ReferenceError!

class Car {
  constructor() {
    this.brand = "Toyota";
  }
}
✕ ReferenceError: Cannot access 'Car' before initialization

Interview Q & A
Q1

Hoisting kya hota hai JavaScript mein? Simple words mein explain karo.

Hoisting JavaScript ka ek behavior hai jisme code execute hone se pehle, engine poora code scan karta hai aur saari variable aur function declarations ko memory mein scope ke top par le jaata hai. Sirf declaration move hoti hai — value assignment wahin rehti hai jahan likhi hai.
Q2

var, let, aur const mein hoisting ka kya fark hai?

Teeno hoist hote hain, lekin initialize alag tarike se hote hain.

var → hoist hota hai aur undefined se initialize hota hai, isliye pehle access karo toh error nahi aata.

let / const → hoist hote hain lekin initialize nahi hote — TDZ (Temporal Dead Zone) mein rehte hain. Pehle access karo toh ReferenceError aata hai.
Q3

TDZ (Temporal Dead Zone) kya hota hai?

TDZ woh time period hota hai jab ek let/const variable ka scope shuru ho chuka hai lekin uski declaration line abhi execute nahi hui. Is period mein variable memory mein exist karta hai lekin usme koi value nahi hoti. Iss time access karo toh ReferenceError aata hai. Ye actually bugs pakadne ke liye helpful hai.
Q4

Function declaration aur function expression mein hoisting ka kya fark hai?

Function declaration → poori tarah hoist hoti hai — naam aur body dono. Isliye declare karne se pehle call kar sakte hain.

Function expression → sirf variable hoist hota hai (var hai toh undefined, let/const hai toh TDZ). Function body hoist nahi hoti. Isliye pehle call karo toh TypeError ya ReferenceError aata hai.
Q5

Yeh code kya output dega aur kyun?

console.log(foo());
console.log(bar());

function foo() { return "foo called"; }
var bar = function() { return "bar called"; };
foo() → "foo called" ✅ — kyunki function declaration poori hoist hoti hai.

bar() → TypeError: bar is not a function ❌ — kyunki var bar hoist hua undefined ke saath, aur undefined() call nahi kar sakte.
Best Practices
✦
var avoid karo let aur const use karo — TDZ ki wajah se bugs jaldi pakad mein aate hain.
✦
Pehle declare, phir use karo Code top-to-bottom padhne laayak rakho, hoisting pe rely mat karo.
✦
Function expressions prefer karo Arrow functions ya function expressions se code predictable rehta hai.
✦
Class pehle define karo Class TDZ mein rehti hai — hamesha pehle define karo, phir use karo.
